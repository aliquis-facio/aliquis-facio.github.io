**점검 개요**

[1페이지: 표지]
안녕하세요. 굿모닝샵 웹 서비스 모의해킹 점검 결과를 발표하겠습니다.
이번 점검은 허가된 범위에서 웹 서비스의 취약점을 확인하고, 실제로 어떤 영향을 줄 수 있는지 분석하는 것을 목적으로 진행했습니다.

[3페이지: 점검자]
점검에는 김도이, 김지원, 배소윤, 전예찬이 참여했습니다.

[5페이지: 점검 항목]
점검 항목은 다른 팀과 동일한 공통 기준을 적용했습니다.

[8페이지: 점검 도구]
점검 도구로는 Nmap, Burp Suite, dirb, sqlmap을 활용했습니다.
이어서 전체 결과와 주요 취약점 사례를 설명하겠습니다.

**결과 요약**

[9 페이지: 「점검 결과 → 총평 및 요약」 집계표]
시간이 부족해 총평을 제대로 작성하지 못했지만 점검 결과, 총 14개 유형에서 35건의 취약점을 확인했습니다.
취약한 패스워드 규칙 1건, 자동화 공격 1건, 불충분한 인가 2건, SQL Injection 5건, Stored XSS 5건, Reflected XSS 1건, 파일 업로드 1건, 결제 금액 조작 1건, 서버 버전 정보 노출 1건, 에러 메시지 주요 정보 노출 4건, 디렉토리 인덱싱 9건, 불충분한 쿠키 관리 1건, 관리자 페이지 노출 1건, 기타 민감 정보 노출 2건입니다.
지난 실습 때 진행했던 내용들은 넘기고 보고서 순서에 따라 각 항목들을 말씀드리겠습니다.

[취약한 패스워드 규칙·자동화 공격은 건너뛰고 불충분한 인가로 이동]

**불충분한 인가**

[18 페이지: 불충분한 인가 점검 경로]
공격자 계정으로 로그인한 후 주문조회 메뉴에 접근하여 본인의 주문내역 및 주문코드를 확인한다.
Burp Suite를 이용하여 주문 상세조회 요청의 idx 파라미터 값을 조작 후 요청을 전송하면 타 사용자의 주문정보를 조회할 수 있다.

**SQL Injection**

[20 페이지: SQL Injection 점검 경로]
굿모닝샵에서는 아이디 중복 확인, 우편번호 검색, 로그인, 상품 검색과 게시판 검색 기능을 점검했습니다.

[23 페이지: 로그인 우회 시도]
여기서는 실제 영향이 명확한 로그인 우회 사례를 보여드리겠습니다.
정상적인 로그인에서는 아이디와 비밀번호를 모두 확인해야 합니다. 하지만 아이디 입력값에 SQL 구문을 조작하는 문자열을 넣어 요청한 결과, 정상 비밀번호 검증을 거치지 않고 로그인되는 것을 확인했습니다.

[24 페이지 victim 계정 표시를 가리킴]
결과 화면을 보시면 victim 계정으로 로그인된 상태가 표시됩니다.

**Stored XSS**

[26 페이지: Stored XSS]
저장형 크로스사이트 스크립팅, Stored XSS입니다.
굿모닝샵에서는 게시판뿐 아니라 주문정보와 회원정보 등 여러 입력 기능에서 스크립트 실행을 확인했습니다. 그중 관리자에게도 영향을 주는 주문정보 사례를 설명하겠습니다.

[27 페이지: 그림 3-24, 주문자·수령자 정보 입력]
먼저 주문서 작성 페이지의 주문자와 수령자 정보 입력란에 실행 여부를 확인하기 위한 스크립트를 넣고 주문정보를 등록했습니다.

[28 페이지]
이 정보는 주문 처리 과정에서 저장되고, 이후 사용자와 관리자가 주문 내용을 확인할 때 다시 출력됩니다.
주문정보 처리 페이지에서는 입력한 스크립트가 실행되어 알림창이 표시됐습니다.
이후 저장된 주문정보가 다른 화면에서도 실행되는지 확인하기 위해 관리자 페이지로 이동했습니다.

[28페이지: 관리자 주문관리 목록]
관리자가 주문관리 목록을 조회했을 때도 저장된 주문정보에 포함된 스크립트가 실행됐습니다.

[29 페이지: 관리자 주문 상세정보]
주문 상세정보 화면에서도 동일하게 스크립트 실행을 확인했습니다.

[나머지 Stored XSS 사례와 Reflected XSS는 건너뛰고 파일 업로드 실행으로 이동]

**파일 업로드 실행**

[37페이지: 자료실 업로드 화면]
파일 업로드 실행 취약점입니다.
자료실에는 PHP나 HTML 파일을 업로드할 수 없다는 안내가 있었습니다. 하지만 실제로는 확장자의 대소문자와 형태를 변경한 파일이 업로드됐습니다.
화면에서 선택한 테스트 파일은 확장자가 PhP3인 파일입니다.

[38페이지: 그림 3-38, 첨부파일 등록 결과]

업로드 후 게시글을 확인하면 변형된 확장자의 파일이 첨부파일로 등록된 것을 볼 수 있습니다.
저장된 파일의 실행되는지 확인하기 위해 업로드된 경로에 직접 접근했습니다.
그 결과 서버 명령 실행에 따른 사용자와 그룹 정보가 반환됐습니다.
화면에 표시된 www-data는 웹 서버 프로세스가 사용하는 계정입니다. 이를 통해 업로드된 파일이 서버에서 실행되고, 해당 프로세스 권한으로 명령이 수행된 것을 확인했습니다.

[결제 금액 조작·서버 버전 정보 노출·에러 메시지 상세는 건너뛰고 디렉터리 인덱싱으로 이동]

**서버 버전 정보 노출**

[45 페이지]
존재하지 않는 URL로 접속한 결과 서버 정보가 노출되는 것을 확인할 수 있습니다.

**에러 메시지로 주요 정보 노출**

[46 페이지]
사이트 내 검색 기능에서 비정상 문자를 입력한 결과 MySQL 오류 메시지와 함께 내부 경로가 노출되는 것을 확인할 수 있습니다.

**디렉터리 인덱싱과 민감 정보 노출**

[50 페이지]
디렉터리 인덱싱과 파일 다운로드 취약점입니다.
`script`, `upload` 등 총 9개의 경로를 찾았습니다.
화면의 script 경로에서는 파일명과 수정 일자, 파일 크기까지 확인할 수 있습니다. 아래쪽에는 웹 서버와 관련 소프트웨어의 버전 정보도 함께 나타납니다.

**기타 민감 정보 노출**

[56페이지: 기타 민감 정보 노출]
여기서 파일 자체에 직접 접근했을 때 어떤 정보가 노출되는지도 이어서 보겠습니다.
lib 폴더에 있는 텍스트 파일에 직접 접근한 결과, 내부 디렉토리 구조와 주요 php 파일명, 업로드 폴더 권한 등의 시스템 구성 정보가 노출되는 것을 확인할 수 있습니다.

[57페이지]
sql 파일에 경우 데이터베이스명과 버전, 구조 등을 확인할 수 있습니다.
