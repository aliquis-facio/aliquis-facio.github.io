# Q. ETH CHANNEL은 왜 최대 8개일까?

기술적으로는 **Cisco 장비의 하드웨어·소프트웨어 구현 제한**이 핵심입니다.

전통적인 Cisco Catalyst 스위치에서는 EtherChannel의 부하 분산 결과를 **3비트 해시값(0~7)** 으로 처리하는 경우가 많습니다.

$$
2^3 = 8
$$

따라서 하나의 EtherChannel에서 동시에 트래픽을 전달하는 활성 링크를 최대 8개까지 직접 선택할 수 있습니다. 즉, **스위치의 전체 포트 수가 부족해서 반드시 8개로 제한되는 것은 아닙니다.**

### 프로토콜별 차이

| 구성 방식                      |   등록 가능한 포트 | 동시에 활성화되는 포트 |
| -------------------------- | ----------: | -----------: |
| 정적 EtherChannel(`mode on`) | 일반적으로 최대 8개 |        최대 8개 |
| [PAgP](PAgP.md)            | 일반적으로 최대 8개 |        최대 8개 |
| [LACP](LACP.md)            |      최대 16개 |        최대 8개 |
| LACP 나머지 포트                |       최대 8개 |  Hot Standby |

LACP에서는 최대 16개를 그룹에 등록할 수 있지만, 전통적인 Cisco 플랫폼에서는 다음처럼 동작합니다.

```text
LACP 채널 그룹: 16개
├─ 활성 링크: 최대 8개
└─ Hot Standby: 최대 8개
```

활성 링크 하나가 고장 나면 대기 포트가 자동으로 활성화됩니다. 어떤 포트가 활성화될지는 `LACP port priority` 등의 우선순위에 따라 결정됩니다. [Cisco Catalyst 9600 공식 문서](https://www.cisco.com/c/dam/en/us/td/docs/switches/lan/catalyst9600/software/release/16-12/configuration_guide/lyr2/configuring_etherchannels.html)

### 왜 무작정 포트를 늘리지 않을까?

* EtherChannel은 보통 **패킷 단위가 아니라 흐름(flow) 단위**로 링크를 선택합니다.
* 포트가 늘어나도 하나의 통신 흐름 속도가 여러 링크 속도의 합으로 증가하지는 않습니다.
* 링크 상태, LACP 정보, 장애 전환 등을 관리해야 합니다.
* 많은 물리 포트를 한 연결에 사용하는 것보다 고속 포트로 교체하는 편이 효율적일 수 있습니다.
* 양쪽 스위치 모두 같은 수의 호환 포트와 처리 능력을 지원해야 합니다.

### 결론

> EtherChannel이 최대 8개인 것은 단순히 스위치 포트 수가 부족해서가 아니라, 전통적인 Cisco 스위치의 **3비트 부하 분산 구조와 플랫폼 구현 한계** 때문입니다. LACP는 16개 포트를 등록할 수 있지만, 일반적으로 8개만 활성화되고 나머지 8개는 예비 링크가 됩니다.

다만 **8개는 모든 제조사와 모든 장비에 절대적으로 적용되는 표준 한계가 아닙니다.** 최신 장비에서는 하드웨어와 운영체제에 따라 활성 링크 수가 다를 수 있으므로, 실제 제한은 해당 모델의 설정 가이드를 확인해야 합니다. Cisco 역시 모델과 포트채널 범위에 따라 4개·8개·16개 등 제한이 다르게 나타납니다.
