**LACP(Link Aggregation Control Protocol)**: 여러 개의 물리적 네트워크 링크를 하나의 논리적 링크로 묶고, 그 상태를 자동으로 관리하는 표준 프로토콜입니다. IEEE 표준을 따릅니다.

### 주요 목적

* 여러 포트의 대역폭을 하나처럼 활용
* 링크 장애 발생 시 나머지 링크로 자동 전환
* 양쪽 장비의 설정이 호환되는지 자동 확인
* 잘못 연결되거나 설정이 다른 포트가 채널에 포함되는 것을 방지

예를 들어 1Gbps 포트 4개를 묶으면 논리적으로 최대 4Gbps 규모의 대역폭을 구성할 수 있습니다.

```text
스위치 A                         스위치 B
  ├── 1Gbps ─────────────────────┤
  ├── 1Gbps ─────────────────────┤
  ├── 1Gbps ─────────────────────┤
  └── 1Gbps ─────────────────────┤
          하나의 Port-Channel
```

단, **한 번의 통신 흐름이 4Gbps로 빨라지는 것은 아닙니다.** 출발지·목적지 MAC/IP 주소 등을 이용한 해시값에 따라 각각의 통신 흐름을 서로 다른 링크에 분산합니다.

### LACP 동작 모드

| 모드        | 동작                |
| --------- | ----------------- |
| `active`  | LACP 협상을 먼저 시작    |
| `passive` | 상대방의 LACP 요청에 응답  |
| `on`      | LACP 협상 없이 강제로 묶음 |

연결 가능 여부는 다음과 같습니다.

| A 장비    | B 장비           | 연결             |
| ------- | -------------- | -------------- |
| Active  | Active         | 가능             |
| Active  | Passive        | 가능             |
| Passive | Passive        | 불가능            |
| On      | On             | 가능하지만 LACP 미사용 |
| On      | Active/Passive | 일반적으로 불가능      |

`passive + passive`는 양쪽 모두 협상을 시작하지 않으므로 채널이 형성되지 않습니다.

### EtherChannel과 LACP의 관계

* **EtherChannel**: Cisco에서 여러 링크를 묶는 기술 또는 기능을 부르는 명칭
* **LACP**: 링크를 자동 협상하고 관리하는 IEEE 표준 프로토콜
* **[PAgP](PAgP.md)**: Cisco 전용 협상 프로토콜
* **Port-Channel**: 묶인 결과로 생성되는 논리 인터페이스

즉,

> LACP로 여러 물리 포트를 협상하여 하나의 EtherChannel 또는 Port-Channel을 구성한다.

LACP에서는 전통적인 Cisco 장비 기준으로 최대 16개 포트를 그룹에 등록할 수 있으며, 보통 **8개는 활성 링크, 나머지 8개는 Hot Standby**로 운용합니다. 다만 실제 제한은 장비 모델에 따라 달라집니다.
