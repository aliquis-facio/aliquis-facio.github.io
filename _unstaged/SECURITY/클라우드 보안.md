- 유연한 용량 계획

- Datacenter(DC)
- Edge Location

### 스토리지 클래스 및 수명 주기

- IT(Intelligent)

- glacier: 아카이브를 사용하는 데 적합하다.

객체가 정기적으로 수행할 작업을 설정할 수 있다.

- 표준 클래스 유지 기간 종료 → 적은 비용의 클래스 → … → 아카이브용 클래스

Standard, Standard-Infrequent Access → 3 AZs 복사
Reduced Redundancy Storage → 1 AZ 복사

glacier는 복원할 때 s3로 옮겨서 복원

### Cloud Front

- AWS CDN 관리형 서비스

### AWS IAM과 접근 권한

정책: 어떤 서비스 기능에 어떤 조작을 할 수 있는지 정의

- IAM 사용자, 그룹 및 IAM 역할, AWS 리소스에 정책을 연결
- json 형식의 정책문서:
	- 필수: `Effect`, `Action`, `Resource`
- 관리형 정책: 재사용 가능
	- AWS 관리형 정책: AWS 제공 → 사용 편함
	- 고객 관리형 정책 → 고객이 직접 생성 → 세밀한 권한 설정 가능
- inline 정책: 싱글 identity (IAM 사용자, 그룹, 역할)에 연결 (policy:identity = 1:1)

다단계 인증: 종류를 따지지 않고 2번 이상 인증한다.
다요소 인증: 두 종류 이상의 인증을 사용한다.

정책 평가 우선순위

IAM 사용자
- AWS 계정 내에서 만들어진 사용자
- 개별 사용자는 고유한 자격증명을 소유
- 부여된 권한의 범위 내에서만 AWS 작업 가능
	- IAM 사용자의 업무 역할에 따라 권한을 부여

IAM 그룹
- 권한을 그룹에 연결하면 그룹 내 사용자들에게 상속의 방식으로 부여
- IAM 사용자는 여러 그룹의 멤버 가능

### 권한 경계(Permission Boundary)

- IAM에서 권한의 최대 범위 제한
- 유저 혹은 역할에 부여할 수 있는 최대 범위 설정
- 교집합 허용

## STS(Security Token Service)

사용자나 애플리케이션에 일시적인 보안 자격 증명(임시 토큰)을 발급해 주는 AWS 웹 서비스이다.

특징

- 단기 유효 기간
- 동적 생성
- 코드 내 보안 강화

주요 활용 사례

- IAM 역할 가정(Assume Role): 다른 AWS 계정의 리소스에 접근하거나, 특정 권한이 필요한 작업 수행 시 임시 권한을 위임받는다.
- 페더레이션(Identity Federation): 기업 내부 디렉터리(Active Directory)나 외부 웹/모바일 사용자(Google, Facebook 등)에게 인증 후 임시로 AWS 접근 권한을 부여한다.
- EC2 및 서버리스 앱: EC2 인스턴스나 컨테이너 내부의 애플리케이션이 안전하게 AWS API를 호출하도록 임시 자격 증명을 제공한다.

## DAS(Direct Attached Storage)

PC와 서버에 다이렉틀 꽂아서 사용하는 스토리지
서버와 하드웨어를 1:1로 연결
하드를 여러 개 끼울 수 있는 서버의 외장하드
서버에 직접 외장저장장치를 연결 → 속도 빠르고 확장 쉬움, 연결 수에 한계

## NAS(Network Attached Storage)

서버와 저장장치가 이더넷 등의 LAN 방식의 네트워크에 연결된 방식
LAN은 TCP/IP 프로토콜 기반이고 저장장치는 SCSI를 사용 → 통신 위해 중계역할을 하는 파일서버가 필요함.
스토리지 내에서 직접 파일을 읽기/쓰기/공유

SCSI(Small Computer System Interface): 컴퓨터 주변기기 접속을 위한 직렬 표준 인터페이스

장점: PORT 수 제한이 없어 확장성과 유연성이 뛰어남, 경제적 유리, 설치 및 유지보수 용이
단점: 접속증가 시 성능저하, DAS보다 전송속도 느림, 파일시스템 공유 → 보안 비교적 취약, 백업이 어려움
